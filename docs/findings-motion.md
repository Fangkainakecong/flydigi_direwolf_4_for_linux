# 体感（角速度）实测：`[14..16]`

> 日期：2026-11-19
> 数据：`data/txt/motion_20261119-003907.txt`（108 336 帧，108.3 s）
> 采集脚本：`scripts/flydigi_motion_capture.py`（回车分段，不掐时间）
> 同一数据也覆盖了 `[21..24]`，结论是**它们不是姿态数据**。

## 结论

* `[14]`、`[15]`、`[16]` 是**三轴角速度**，各 1 字节、有符号（`int8`）。
* 平放完全静止时三字节全为 0（A1 阶段 99.3% 的帧为 `0,0,0`）。
* 绕竖轴转（yaw）→ `[14]` 主导；点头（pitch）→ `[15]` 主导；横滚（roll）→
  `[16]` 有反应但幅度小、且量化极粗。
* 值**不是每帧更新**：约 89 Hz 更新一次，两个采样点之间的 10 来帧全是重复值。
  （A4 阶段 7.0 s 内共 620 次变化 → 89 Hz。）
* **`cmd17` 不是体感的开关**：B 段（发过 `A5 5A A5 11 07 01 01 FF FF FF ...`
  且被 ACK）与 A 段的统计没有区别，标准 32 字节报文里一直带着运动数据。
* `[21..24]` 在全部 7 个阶段都稳定在 `128/130/129/126` 附近（±1），**不随
  转动变化**，是状态字节而不是姿态角/四元数。

## 分段统计

各阶段三轴（按 `int8` 解读）的 RMS。全零比例越高说明越静止。

| 阶段 | 内容 | 帧数 | 全零 | rms[14] | rms[15] | rms[16] |
|---|---|---|---|---|---|---|
| A1 | 平放静止 3 s | 2 801 | 99.3% | 0.1 | 0.0 | 1.4 |
| A2 | 手持不动 | 17 002 | 58.4% | 1.1 | 2.1 | 7.3 |
| A3 | yaw 左右各 45° | 12 000 | 18.6% | **26.0** | 3.1 | 10.8 |
| A4 | pitch 前后各 45° | 7 000 | 2.5% | 4.2 | **44.4** | 10.4 |
| A5 | roll 左右各 45° | 5 000 | 2.0% | 8.8 | 10.8 | **11.3** |
| B1 | cmd17 后放下 | 2 301 | 12.3% | 9.9 | 21.3 | 8.2 |
| B2 | cmd17 后左右晃 | 2 701 | 67.9% | 4.2 | 14.9 | 5.9 |

A3 的 `[14]` 是 `[15]` 的 8 倍、A4 的 `[15]` 是 `[14]` 的 10 倍，轴向归属
没有歧义。A5 的横滚没有做出干净的隔离（用户做动作时会带一点俯仰），
所以第三轴只能算"疑似"。

`[16]` 在 A4 整个阶段只出现过 4 个值：

```
0x00 (0)   2674 帧     0x0F (+15) 1702 帧
0xF0 (-16) 1460 帧     0xFF (-1)  1164 帧
```

取值落在 `0x0F`/`0xF0` 这种"低半字节/高半字节全 1"的形态上，更像是
**4 位字段被展开到 8 位**，而不是一个连续的 8 位轴。需要一次"只绕前后轴
慢慢滚、不做其他动作"的采集来定性（见下）。

## 尚未确定

1. `[16]` 的编码（4 位？带符号？量纲？）。
2. 三轴的单位与零偏：`int8` 的量纲未知，做体感鼠标前需要标定
   （至少要知道满量程对应多少 °/s）。目前的用法可以是纯相对的
   "有转动就积分"，但手感需要标定。
3. 采样率 89 Hz 是固件内部速率，与 1000 Hz 的报文率无关；做鼠标时
   只能按 89 Hz 的有效样本积分。

## 快速转动的 ±127 回绕（2026-11-21）

快速转动时 `[14]` 会出现 **+125 → -124** 这种跳变，中间没有经过 0；
这是 int8 在 ±127 处的回绕，不是真实反向。用 89 Hz 的采样看，真实反向
会在大约几十毫秒内经过 0 附近，不会直接跳边界。

映射层用 `report.deskew_gyro()` 处理：相邻样本都接近边界（|v|>90）且
跳变 >200 时，按连续性补 ±256。这样快速转动会得到 128..255 的幅值，
鼠标不会反向；真实反向经过小值，不触发。标定积分也走同一个函数。

## 官方参数里有什么（2026-11-21 复核）

结论：**没有可用的物理标定值。**

* 840 字节配置里的体感块（offset 137..144）只有：目标（off/左摇杆/右摇杆/
  鼠标）、开启键、开启方式、死区、灵敏度 x/y、use mode。出厂值是
  `deadzone=8`、`sensitivity=(25, 25)`（见
  `data/txt/factory_fp4_20261119-214700.txt`）。
* 没有 `counts_per_degree`、零偏或轴符号字段。
* 上游 openflydigi 的 `flydigi/motion.py` 里 `GYRO_SCALE = 1.0`，注释明确写
  了 "there is no reference to check Flydigi's LSB-per-deg/s against"；
  Space Station 的 Gyro→Mouse 是 Windows 端 `KeyboardMouseInjectRunner`
  用未公开常数做的，配置文件只保存灵敏度/死区偏好。
* 因此"官方参数"只能影响手感（灵敏度/死区），替代不了物理标定。

本项目的默认估算值 `0.67 raw·s/°` 来自 2026-11-21 的 3 圈标定：

* 水平 3 圈（1080°）积分 706 raw·s → 0.654；
* 低头 90° 积分 61.8 raw·s → 0.687；
* 两者相差 5%，说明尺度自洽。

更早用 A3 阶段（"yaw 左右各 45°"）估出的 13.4 是**错的**：那段动作里
三轴积分几乎一样（x=1206、y=1055、z=1210），说明混入了滚转/俯仰，
不能把 90° 全算到 yaw 上。`calibrate --estimate` 现在写 0.67，只作为
不想做动作时的起步；要更准仍用默认 3 圈标定，拿到数据表/官方常数则用
`--set-yaw` 直接写。

## 下一次采集怎么做

只跑一个动作即可，脚本里把 A 段换成"慢速横滚"重复 3 次：

```bash
sudo python3 scripts/flydigi_motion_capture.py
```

如果要做标定，再补一个"匀速转 360°、数秒数"的动作，就能把 `int8`
换算成 °/s。

## 加速度计实测（2026-11-19）

用一个"静态姿态"实验补上了 `[21..24]` 的性质：
`scripts/flydigi_accel_probe.py` 让手柄保持 7 种姿态各 2 秒，再保持水平上下颠 2 秒。
数据 `captures/accel_20261119-011738.bin`（011453 复测一致）。

| 姿态 | `[14]` | `[15]` | `[16]` | `[24]` |
|---|---|---|---|---|
| 平放正面朝上 | 0 | 0 | 0 | 126.9 |
| 正面朝下 | 0 | 0 | 0 | **133.0** |
| 四边朝下（左/右/充电口/握把） | 0 | 0 | 0 | 127.0 |
| 水平上下颠 | sd 36 | sd 67 | sd 14 | sd 0.19 |

* 角速度三轴在七种姿态下均值都是 0 —— 陀螺仪不受重力影响，正确。
* 只有 `[24]` 跟踪重力方向：正面朝下 +6，翻面过程中平滑经过 128/130/131/132。
* 但 `[24]` 对线性加速度毫无反应（上下颠时 sd 0.19），且只有约 3 counts/g，
  所以它是**固件算出的低分辨率朝向字节**，不是加速度计原始输出。

**结论：标准报文里没有可用的加速度计数据。** 三轴角速度是唯一的运动数据。
如果硬件带六轴 IMU，加速度计只在固件内部用（可能就用来生成这个朝向字节），
没有暴露给主机。要拿到它只能走老方言 raw 流（`cmd80`，sub-id 未知）。

### 数据质量
