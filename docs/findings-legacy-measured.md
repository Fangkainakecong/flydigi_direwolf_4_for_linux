# 冰原狼4 老方言实测记录（2.4G，Linux usbfs）

> 日期：2026-11-19
> 设备：`045e:028e`（dongle），`DeviceType=132`（FP4），固件 4.0.7.2
> 脚本：`scripts/flydigi_old_dialect_probe.py`、`scripts/flydigi_legacy_blob_read.py`
> 上游背景（Vader 4 Pro 的同类测量）：[findings-other-devices.md](findings-other-devices.md)

## 传输

与上游记录一致，本机全部复现：

* 帧 15 字节 `[0]=0xA5, [1]=命令号, [2]=子命令, [3..]=载荷`，无校验，写 EP `0x05`
* 回包不走单独的端点，而是**注入在 32 字节手柄报文 `[14]` 之后**：
  `[14]=0xA5`，`[15]=应答的命令号`，`[16..]` 随命令不同
* 正常手柄帧的 `[14..15]` 是 `00 00`，所以用 `[14]==0xA5` 即可区分
* 需要先把接口从 xpad 抢过来（这期间手柄在系统里不可用）

## 识别（cmd 16）

回包 `[14..31]`：

```
a5 10 84 cf 53 65 38 40 72 03 02 00 06 02 00 00 a9 00
│  │  │  └────┬────┘ └──┬───┘ │  │  │  │  │  └──┬──┘
│  │  │       │         │     │  │  │  │  │     └ 校验/保留
│  │  │       │         │     │  │  │  │  └ [27] 当前槽位
│  │  │       │         │     │  │  │  └ [26] 0x06
│  │  │       │         │     │  │  └ [25] 连接方式（0=2.4G，1=有线）
│  │  │       │         │     │  └ [24] 0x02
│  │  │       │         │     └ [23] 电量 3
│  │  │       │         └ [21][22] 固件 4.0.7.2（十进制半字节：0x40→4.0，0x72→7.2）
│  │  │       └ [17..20] uid cf536538
│  │  └ [16] DeviceType 132 = FP4（冰原狼4）
│  └ [15] 应答 = 0x10（=命令号本身）
└ [14] 0xA5
```

固件按十进制半字节读：上游在 Vader 4 Pro 上读到 `6.9.3.3` 对应字节 `69 33`，
本机读到 `40 72` 即 `4.0.7.2`。

## 配置版本（cmd 80 sub 4）

回包 `[14..31]`：

```
a5 50 04 76 e5 6c a5 96 61 75 ef 00 00 00 00 00 bc 00
│  │  │  └────────────────┬───────────────┘
│  │  │                   └ [17..24] 四个槽位的 data_version，uint16 小端
│  │  └ [16] 子命令 4
│  └ [15] 应答 = 0x50（=命令号）
└ [14] 0xA5
```

四个值是 `0xE576 / 0xA56C / 0x6196 / 0xEF75`。**第一个恰好等于槽位 0 blob
偏移 225 处的 data_version（58742）**，所以槽位是 0 基的，且这个命令能一次性
拿到 4 个槽位的版本号 —— 切换配置时可以用它判断"哪个槽位被改过"。

## 读配置（cmd 33 → 应答 34）

请求：`A5 21 <槽位> 0A`（`0A` = 每包 10 字节）

回包 `[14..31]`：

```
a5 22 03 54 20 04 28 a0 00 00 ff 00 00 ff 00 00 ff
│  │  │  └──────────────┬──────────────┘
│  │  │                 └ [17..26] 包内数据 10 字节
│  │  └ [16] 包索引 0..83
│  └ [15] 应答 = 0x22（34 = 命令号+1）
└ [14] 0xA5
```

* 手柄会**连续吐 84 个包**，每包 10 字节，共 840 字节；不需要逐包应答
* 包可能乱序、也可能重复（本次 86 个包里索引 11 和 55 各重复一次），按索引拼即可
* **空槽位不回应答**（槽位 1 一个包都没有），这就是"没有配置"的表示
* 拿到 blob 后直接用 `reference/openflydigi/mapping.py` 解析，格式与 Apex 5 同构

## 四个槽位的实测内容

| 槽位 | data_version | 标题 | 键位表 |
|------|--------------|------|--------|
| 0 | 58742 (0xE576) | 配置1 | A/B/X/Y/RB 开 turbo；M1→B、M2→A，都带 turbo |
| 1 | — | — | 空槽位（无应答） |
| 2 | 24982 | 配置3 | **全部 18 个键 → 254（键盘哨兵）** |
| 3 | 61301 | 配置4 | 全默认（除 `right` 的频率字节残留 15，模式 0，不起作用） |

键位表在偏移 13，每键 3 字节 `[目标, turbo模式, 频率]`，`255` = 保持自身。

### turbo 编码

`turbo模式`：`0` 关闭、`1` 按住连发（`TURBO_WHILE_HELD`）、`2` 切换式。
`频率` 非 0 时生效。实测 A（频率 15）按住时位图约每 **0.2–0.3 秒**通断一次，
Y（同为 15）约 0.2 秒，抖动较大，暂时不下"周期=f(频率)"的结论 —— 重要的是
**连发是固件自己做的**，Linux 侧看到的就是普通的按下/松开序列，不需要复刻。

### 槽位 2 是"键盘哨兵"的实证

把 18 个键全部写成 254 后，固件会**抑制这些键的手柄输出**（上游用
`tools/keyboard-target-probe` 在 A 上验证过），但具体键码**不存在 pad 上** ——
它在 Space Station 自己的 PC 端配置里。所以 Linux 上 254 等于死键，
真正的键盘映射只能由我们的 daemon 自己维护（见
[findings-onboard-remap.md](findings-onboard-remap.md)）。

## 当前槽位会变

两次识别之间（中间跑过按键探针的自由记录模式，按了几次 FN 组合），
`[27]` 从 2 变成 0 —— 说明**手柄自己可以切配置**，`[27]` 就是当前槽位。
daemon 要么只在启动时读一次，要么周期性地重新识别（后者更稳）。

## 对 daemon 的意义

1. **读**：完整可用。拿到 blob 就能知道每个键是不是被改成别的键、是不是
   turbo、是不是键盘哨兵/宏。
2. **写**：上游标注"未验证"。目前没必要——配置在 Windows 里改就行，
   Linux 侧只负责按配置解释输入。
3. **键盘映射**：只能主机侧实现（uinput / 直接注入事件），pad 上只有哨兵。
4. **profile 切换**：`cmd80 sub4` + `[27]` 足够判断当前槽位与版本变化。
