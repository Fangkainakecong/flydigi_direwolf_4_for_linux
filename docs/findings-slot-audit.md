# 板载四槽实测：哪个槽能交给 daemon

> 日期：2026-11-19 21:33
> 设备：`045e:028e`，固件 4.0.7.2，DeviceType=132，uid `cf536538`
> 数据：[data/txt/blob_audit_20261119-213331.json](../data/txt/blob_audit_20261119-213331.json)
> 复现：`sudo python3 scripts/flydigi_blob_audit.py`
> 离线复看：`python3 scripts/flydigi_blob_audit.py --from data/txt/blob_audit_20261119-213331.json`

## 1. 结论先说

**当前槽位 3（板载"配置4"）可以直接交给 daemon，不需要去 Windows 改任何东西。**

它是四个槽里唯一**没有任何键位重映射**的，所以：

- M1/M2/FN/Turbo 会原样出现在 `[19..20]` 位图里；
- 标准按钮字完全等于物理按键，没有"按 M1 却报 R3"的歧义；
- 唯一的残留是**板载体感映射开着（target=mouse）**，在 XInput 模式下属惰性，见 §4。

切槽用 FN+方向键即可，daemon 只读 `[27]` 做提示，不参与切换。

## 2. 四槽对照

| 槽 | 标题 | data_version | 重映射 | 板载体感 | 判定 |
|---|---|---|---|---|---|
| 0 | 配置1 | 58742 | `right/a/b/x/y/rb` → 自身 + turbo 15Hz；`m1→b` + turbo 20Hz；`m2→a` + turbo 20Hz | off | 可接管，但 turbo/m1m2 重映射会让 daemon 分不清物理键 |
| 1 | 配置2 | 42348 | `m1→r3`、`m2→l3` | off | 可接管；M1/M2 会改报 R3/L3 |
| 2 | 配置3 | 24982 | 18 个键 → **键盘(254)**，另 `down` 带 turbo 15Hz | **mouse** | **不可用**：Linux 下全是死键 |
| 3 | 配置4 | 61301 | **无** | **mouse** | **推荐** |

"可接管"的判定只有一条：**有没有物理键被固件吃掉**。

- 目标 254 = 键盘。固件转而发 HID 键盘报文，而 dongle 只有一个厂商接口，
  Linux 侧收不到这些键 → 死键。
- 目标 32 = 宏。键本身不再上报，只跑宏 → 同样是死键。
- 目标 255 = "自身，不变"；非零频率 = turbo（固件自己连发）。

## 3. 为什么"含扳机马达配置"是误报（已修）

第一版审计把 `blob[154..183]` 全零当作"没配扳机马达"，结果四个槽全中。
查 `reference/openflydigi/mapping.py`：

```
145..154  grip vibration
154..183  trigger motors        # 1 个使能字节 + 两侧各 14 字节
ENABLED, DISABLED = 0, 0xFF     # 反逻辑
```

出厂默认这一块就**不是全零**（min/max/scale 有默认值），所以"全零"根本不是判据。
现在只看使能字节 `blob[154] == 0`，且它对 daemon 完全无影响（扳机马达是硬件
震动，不参与输入读取）。

同理，"干净"原来要求体感也关闭，过严：体感开不开都不影响 M1/M2 上报。

## 4. 板载体感开着的实际影响

槽 3 与槽 2 的体感块：

```
target = 3 (mouse), 开启方式 = click, 死区 = 8,
灵敏度 = (25, 25), 用途 = fps, 附加键 = lt / up
```

- XInput 模式的 32 字节报文里**没有鼠标通道**，实测所有帧长度恒为 32，
  输入率仍 ~1000 Hz（`captures/inputs_20261119-002308.bin`：242538 帧 / 270.8 s）。
- 因此这条映射在 Linux 上不会产生鼠标事件，也不会与 daemon 抢；
  属于"惰性配置"。
- 稳妥做法：在 Windows 空间站把槽 3 的体感关掉（或用槽 1），
  避免以后固件升级改成在 XInput 下也发鼠标报文。**不是阻塞项。**

## 5. 对 daemon 的要求

1. **启动审计**沿用本脚本的判定：`daemon_ok = 没有键映射到 254/32`。
   不通过时警告并列出被吃掉的键，但**仍然启动**（用户可能就想这么配）。
2. **不要写 blob**。所有映射在主机侧做，板载槽只读，避免和 Windows 空间站互相覆盖。
3. **板载槽号只做提示**：`[27]` 变了就刷新一次审计结果（FN 组合可能切槽）。
4. **重映射槽要降级提示**：如果当前槽有 `m1→r3` 这类重映射，
   daemon 会把 M1 当 R3 处理（因为固件就是这么报的），界面上要说明。

## 6. 待确认（下一步 control_probe）

- 槽 1 的 `m1→r3` 到底是"标准字报 R3 + 位图仍置 m1 位"，还是"两者都变 R3"。
  `flydigi_control_probe.py` 在**槽 1** 跑一次就能定；槽 3 没有重映射，测不出这个。
- SELECT+A/B/X/Y 在固件里是否完全无副作用（会不会切板载槽）。
- Home 短按/长按行为。

## 7. 后续实测：SELECT + A/B/X/Y 是**固件的切槽键**

`flydigi_control_probe.py` 第一次跑（21:4x）就撞上了：

| 操作 | 标准按钮字 | 位图 | 槽位（`cmd16`） | 报文流 |
|---|---|---|---|---|
| 只按 SELECT | `back` | `back` | 3 → 3 | 停 1.0 s |
| SELECT + A | `a`（**没有 back**） | `a` + `menu` | **3 → 0** | 停 0.7 s |
| SELECT + B | `b`（**没有 back**） | `b` + `menu` | **0 → 1** | 停 0.7 s |

三条结论：

1. **SELECT+A/B/X/Y 就是固件自带的"切板载配置"**，和我们原本打算在 daemon 里
   实现的软件四槽完全重合。A→槽0、B→槽1（X/Y 应为 2/3，待补测）。
2. 切槽时报文流**停 0.7–1.0 秒**，但设备路径不变（没有重新枚举），
   所以不用重新 claim，只要排空 + 重试 `cmd16`。
3. 组合键期间 SELECT **不在标准字里**（不会被当成 Back），而位图里会出现
   `menu`（bit 24）。也就是说固件给了主机侧一个"这是组合键"的显式标记。

> 位图 bit 24 在 `KEY_NAMES` 里叫 `menu`，我们此前把同一颗物理键叫 FN。
> 也就是说 FN 和"SELECT 作为修饰键"共用这一位，二者只能靠上下文区分。

**对方案的影响**：daemon 改为**跟随固件槽位**，不再自己做组合键仲裁。
详见 [docs/daemon-plan.md](daemon-plan.md) §5.6。

**探针顺带修的问题**：切槽后 `cmd16` 会连续无应答，原来直接
`identify(link)['slot']` 会抛 `TypeError` 把整轮数据丢掉。现在的处理是
重试 10 次 + 异常也落盘 + 记录是否重新枚举。

## 8. 出厂配置：`default_mapping_132.dat`

空间站自带的出厂文件在
`Configs/Controller/fp4/default/default_mapping_132.dat`（6814 字节，4 个槽位）。
用上游 `tools/mapping_bean.py` 翻译成 840 字节后：

```
出厂槽 0..3：完全相同，只在 774 字节处不同（标题里的数字）
  协议 0x0301，data_version = 65535
  键位表：全部默认（32 项全是 0xFF）
  体感：off，开启键=lt，死区=8，灵敏度=(25,25)
  扳机马达：关（使能字节 0x01；0=开，1=关，和 grip 块反着）
  握把马达：00 00 3c ff 32 00 50 ff 32
```

和手柄当前内容（空间站 `onboard/*.dat` 转出来的 blob）逐字节比：

| 槽 | 不同字节 | 差异 |
|---|---|---|
| 0 | 25 | 键位表 6（m1→b、m2→a + turbo）、摇杆曲线 4、握把马达 3、扳机马达使能、data_version、摇杆扩展 9 |
| 1 | 21 | 键位表 2（m1→r3、m2→l3）、摇杆曲线 4、握把马达 3、扳机马达使能、data_version、摇杆扩展 9 |
| 2 | 47 | 键位表 18（全键盘）、体感 4、握把马达、扳机马达使能、摇杆扩展 15 |
| 3 | 25 | 体感 4（`00 0c 00 08` → `03 ff 00 00`）、扳机马达使能、摇杆扩展 14 |

**"摇杆扩展"那 9–15 字节大概率是每台手柄的摇杆 ADC 标定**（`cmd20` 读的那组），
出厂文件不可能带，所以永远会不同，不是"被改过"。

**扳机马达使能**：出厂是 `0x01`（关），你的手柄是 `0x00`（开）——
四个槽都被空间站打开过。对 daemon 无影响。

复现：

```bash
python3 scripts/flydigi_bean_translate.py                 # 打印四个出厂槽
python3 scripts/flydigi_bean_translate.py --diff <blob.bin>   # 和实机对比
```
